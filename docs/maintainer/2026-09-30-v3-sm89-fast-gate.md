# v3/sm89 fast-gate report — 2026-09-30

This report records the first device-executed qualification of the v3 integration branch on the
local 48 GiB RTX 4090. It is a routine-iteration fast gate, not a release benchmark or a substitute
for the full validation matrix.

## Identity and conditions

- branch: `sync/2026-09-30-v3-sm89`
- tested source before the compatibility commit: `f40d1950`
- artifact: `/data/llm/ninfer/models/qwen3_8_27b_v3.ninfer`
- artifact SHA-256: `81f924d440c27261d820c19a9f8d45794c5aee410f8a68bd358133fa8c0375da`
- build: Release, CUDA 13.1, GCC 14, `CMAKE_CUDA_ARCHITECTURES=89`
- runtime: INT8 KV, 262,144 maximum context and KV capacity, one active lane,
  `--prefill-chunk 1024`, CUDA Graphs enabled, greedy sampling
- comparison request: one 74-token Chinese prompt, 128-token output limit
- medium request: 5,891 prompt tokens, 64-token output limit

Five focused artifact/loader/frontend tests passed during the gate:
`ninfer_artifact_reader_test`, `ninfer_artifact_materialization_test`,
`ninfer_artifact_writer_interop_test`, and `ninfer_qwen3_5_loading_test`.
The fifth, `ninfer_qwen3_5_frontend_test`, also required adapting two fork-local cases from the
deleted target-specific factory API to the v3 model frontend API.

The v3 MTP3 short-request decode rate is 2.10 times the v3 no-speculation rate for this one prompt.
MTP3 matches the production v2 decode rate and acceptance within this deliberately small sample.
Resident GPU memory after the short v3 MTP3 request was approximately 26,970 MiB; server startup
reported 16.7 GiB of loaded weights, 9.30 GiB of runtime allocation, and 21.1 GiB free after sizing.

## Finding and fix

The first v3 startup loaded weights and then rejected the official artifact because its maintained
`frontend/chat_template.jinja` intentionally differs from the Hugging Face compatibility template
embedded in `tokenizer_config.json`. The maintained resource has SHA-256
`a497db9e663941e6f7a05307c2bafa8374c12e142ad1fbea6229888d41f1ab16`.

The integration branch now treats the artifact resource as authoritative, admits that exact
maintained hash as the Qwen3.8 reasoning-effort template, and still rejects every unknown template.
This is a bounded compatibility bridge. A later iteration should port upstream's complete generic
Jinja executor and its tests rather than broadening the allowlist.

## Operational outcome

The canary used loopback port 24562 and was stopped cleanly. The existing v2
`inferctl switch ninfer-single` service was restored on port 24561 and passed `/health` after the
test. ComfyUI remained running on the separate RTX 5060 Ti throughout.
