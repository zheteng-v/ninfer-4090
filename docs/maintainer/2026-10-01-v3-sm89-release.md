# Qwen3.8 v3/sm89 release record — 2026-10-01

## Decision

The `release/v3-sm89` candidate is accepted for production canary and promotion on the local
48 GiB RTX 4090. It loads the official v3 Qwen3.8 artifact, preserves the native no-Docker
deployment, restores durable session slots and the complete Serve contract, and passes the long
context correctness matrix. The previous production source is retained by the annotated tag
`v2-sm89-production-2026-09-30`; its artifact remains immutable.

This is a correctness and product-envelope release, not a claim that v3 wins every v2 performance
cohort. Same-condition measurements show essentially unchanged 64K prefill but roughly 9–10%
slower decode in the two sampled cohorts. CUDA Graph construction also takes about 9.5 minutes on
this host. Both results are explicit follow-up targets rather than hidden by best-case numbers.

Both binaries used one lane, INT8 KV, MTP3, Vision, greedy no-thinking sampling, disabled prefix
reuse, 262,144 maximum context and capacity, on the same GPU. The values are single controlled
samples, so differences below 3% are not treated as performance claims.

| Cohort | v2 | v3 | Difference |
|---|---:|---:|---:|
| Python code decode | 149.36 tok/s | 135.37 tok/s | -9.36% |

| 64K NIAH decode | 149.59 tok/s | 134.32 tok/s | -10.21% |

Both code responses contained the required `pyproject.toml`, `asyncio`, `JSONL`, and `pytest`
elements, and both 64K responses matched the exact oracle.

## Dual-lane interpretation

The 204,800-per-lane, 409,600-total-KV profile starts successfully at 14.6 GiB runtime reservation.
Two near-200K prompts both completed with exact output when a long pending timeout was configured.
At both near-200K and 128K depths, however, the scheduler serialized long prefill admission. A
128K second request hit the temporary command's default 30-second timeout while the first completed
at 1,612 tok/s. Production explicitly sets `--pending-timeout-ms 600000`; callers must understand
that two lanes provide capacity and decode isolation, not simultaneous long-prefill throughput.

## Reproduction commands

Configure and build:

```bash
cmake -S . -B build-native -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=/usr/bin/gcc-14 \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++-14 \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-13.1/bin/nvcc \
  -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-14 \
  -DCMAKE_CUDA_ARCHITECTURES=89 \
  -DPython3_EXECUTABLE=/data/llm/sglang/venv/bin/python \
  -DNINFER_BUILD_APPS=ON -DBUILD_TESTING=ON -DNINFER_BUILD_BENCHMARKS=OFF
cmake --build build-native -j
ctest --test-dir build-native --output-on-failure
```

The exact request payloads are the tracked `examples/cli/messages/text_smoke_zh.json`,
`scenario_code_python.json`, and `long_niah_{8k,64k,128k,256k}.json`. The deployed command is
assembled by `.local/start-native.sh` from `.local/ninfer.env` or
`.local/ninfer-dual-200k.env`. Machine-readable results and the key launch arguments are retained
in the companion JSON report.

## Rollback and follow-up

Before promotion, the clean rebuilt v2 binary loaded the tagged source and immutable v2 artifact
on canary port 24562, passed `/health`, model discovery, and the deterministic answer `42`, then
shut down cleanly. Production promotion must retain that binary, artifact, configuration, and tag.

Follow-up priorities are measured, in order: cache reusable CUDA Graphs or reduce their shape-build
cost; profile the v3 decode regression at Q5/Q6/Q8 projections and GDN/KDA recurrence; make dual
long-prefill admission behavior explicit in metrics and documentation; then benchmark upstream
candidate PRs against this immutable baseline.
